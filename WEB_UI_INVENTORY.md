# Codex WebUI interface inventory

Source inspected: running local service at `http://127.0.0.1:4545`, backed by `/home/vlad/apps/codex-webui/public/{login.html,index.html,app.js,dictation.js,viewport.js,app.css}` on 2026-10-16. `GET /` redirects to `/login.html` without authentication and `/api/session` returns 401. The sign-in page was checked over HTTP; authenticated workspace behavior below was traced from the live service's local source, not exercised through a signed-in browser. This is an inventory of the interface, including UI-only and unavailable controls, rather than a claim that every backend action was tested.

## Routes and overall structure

| Route / target | Interface |
| --- | --- |
| `/login.html` | Public sign-in page. The only separate page in the UI. |
| `/` (also `index.html` when authenticated) | Single-page workspace: sidebar, top bar, conversation/empty state, activity rail, approval drawer, persistent composer, and three modal overlays. Thread selection does not change the URL. |
| `/api/image?path=…`, `/api/file?path=…` | Opened by message images and gallery preview/download links in a new tab or as a download. These are content targets, not navigation pages. |
| `https://agentmediatools.com/tip?...` | External optional tip page, linked from login and opened from the tip modal. |

The application uses native browser dialogs only for `/rename` (`prompt`) and `/archive` (`confirm`). Its other overlays are in-page. The browser document title is `Codex WebUI` in the workspace and `Codex WebUI · Sign in` on login.

## Sign-in screen

- Centered dark card with gradient green `C` logo, `SELF-HOSTED · FREE FOREVER` eyebrow, `Codex, from anywhere.` heading, explanatory copy, and a display-only security note with green dot.
- Labeled password input (autofocus, `current-password`, required) and full-width **Open workspace** submit button. Submission disables the button, clears earlier error, posts the password, redirects to `/` on success, or shows the server message in an alert area and selects the password on failure.
- Optional tip link opens a new tab. The sign-in card scrolls if viewport height is small; mobile input/button targets are at least 48 px and input font is 16 px.

## Main shell and sidebar

- Desktop shell is a fixed-height two-column grid: 288 px sidebar plus workspace. The sidebar has logo, `Codex WebUI`, `Self-hosted · free`, and **＋ New thread**. New thread clears the active conversation, plan/activity, title, tokens, active thread storage, and composer text, retains/chooses a workspace, restores the new-thread draft, focuses the composer, and closes the mobile sidebar. It does not create a server thread until first send.
- **Thread status** strip shows computed counts `N working`, `N need input`, and `N idle`. These chips are display-only. `need input` reflects the current pending approval count as 0 or 1; it is not a per-thread inbox.
- **Search threads…** filters the already loaded thread list immediately by title, current working directory, or ID. It does not trigger a server search. `No matching threads` and `No threads yet` are distinct empty states.
- `THREADS` header contains **Select**/**Done**, conditional **Select all**/**Deselect all**, and **Refresh**. Selection mode adds check circles and a bar with selected count and **Archive**; refresh is hidden in selection mode. Select all operates on the currently filtered/loaded visible IDs. **Load more sessions** appears only when a next cursor exists. Buttons disable during loading/archive.
- Each thread row shows title, `working`/`idle`, updated/created local date-time, last component of working folder, and a spinner when active. Current thread and selected rows have separate emphasis. Pinned rows sort before others; active rows sort before inactive among otherwise equal rows. The star (`☆`/`★`) toggles a browser-local pin. Clicking a normal row opens it without navigation. A 500 ms hold enters selection mode with that row selected. Swipe left reveals a red **Archive** action; a longer swipe immediately archives. Clicking a revealed row closes its reveal. Right-click context menu is suppressed on rows.
- Archiving supports one or many rows, uses batches of 500, shows result/error toasts, removes successfully archived rows, and opens the new-thread state if the active row was archived. An active-writer failure tells the user to close the session and retry. `/archive` has an additional native confirmation before using the same archive flow.
- Sidebar footer shows connection indicator and label: `Connecting`, `Codex connected`, `Reconnecting…`, `Agent offline`, or `Connection failed`. The dot is green only when connected. Actions: **⚙ Prefs**, **▦ Files**, **♡ Tip**, **Sign out**. Sign out ends this WebUI browser session and redirects to login; it is separate from Codex credential logout.

## Top bar and central pane

- Top bar shows current thread title (default `New thread`) and full workspace path (`Choose a workspace to begin`/`Local workspace` fallback). Long values ellipsize. Three usage chips: `Chat · —` or cumulative chat tokens; `Model · session only` or provider rolling-limit/credits summary; optional `AMT · remaining/limit today · credits` only when connected. Provider chip turns green when data is present, amber near low remaining; hover title gives each available limit and reset time. All three are display-only.
- **Resume after limit reset** checkbox is a per-thread (or as-yet-new-thread) action. When enabled, a failed rate-limited turn/message may be retried or continued after reported reset. Adjacent status chip shows a countdown `Resume in …` or `Checking limit…`, with reset time on hover. It is hidden without pending work. Unchecking removes the pending resume. The timer updates every second; absent reset time yields an error toast.
- Permission pill (`Restrictive`, `Moderate`, or `YOLO`) and ready/working status pill are display-only; the pill text is controlled by preferences. Status distinguishes **Working in this chat**, `N running in background`, and **Ready**. **Copy** copies the most recent assistant bubble to clipboard, or shows an error toast if none. **Export** downloads current rendered user/assistant messages as a timestamped Markdown file, or reports nothing to export. **Activity** toggles the rail. **Stop** appears while the selected thread is running and interrupts its current turn. The activity button pulses while any thread is active.
- New/empty view has a large `C` orb, `SELF-HOSTED · FULL ACCESS`, heading, explanatory text, decorative badges `Free forever`, `Your machine`, `Optional tip`, a labeled **Working folder** select, and three prompt shortcut buttons. The folder select is populated from server workspaces, defaults to `media-tool` if present, otherwise first folder; changing it updates current working folder and labels. Shortcut buttons immediately send these exact prompts: architecture exploration; read-only git status/recent-work summary; read-only checks/project-health report. They create a thread as needed.
- Conversation view replaces empty view once messages exist/opened thread. User and Codex messages have `Y`/`C` avatars and `YOU`/`CODEX` labels. User messages have a tinted bubble; assistant text is unboxed. Markdown support in the renderer: paragraphs and line breaks; headings levels 1–3; bold, italic, inline code, fenced code blocks with optional language label; ordered/unordered lists; blockquotes; rules; HTTP(S)/local/hash links; local/data images. Image links open full image in a new tab; failed images become text placeholders. This is a limited custom renderer (for example, it does not provide table syntax or a code-copy button). Streaming text is plain/prewrapped until finalized.
- Commentary/progress messages are grouped in expandable `Progress · N updates` details cards. A live commentary update expands the card; completion collapses it. Conversation event cards show `Thread opened` when no retained messages, `Action approved`/`Action denied`, and `Turn interrupted`. Auto-scroll follows new output while near bottom, pauses when the user scrolls away, and displays **↓ Jump to latest** until scrolled down. Focusing the composer while near bottom keeps latest content visible around virtual keyboard changes.

## Composer, commands, attachments, dictation, queue

- Persistent composer includes attachment/paperclip button, multiline `Message Codex… (/ for commands)` textarea (50,000-character maximum), microphone button, **Reasoning effort** select (`Default`, `Low`, `Medium`, `High`, `Extra high`), **Dictation language** select (`Auto`, `Русский`, `English`), desktop-only current working path, and upward-arrow **Send**. Textarea grows to 120 px. Enter sends; Shift+Enter inserts newline. A send with no text and no attachment does nothing. Sending creates a thread if needed, shows an optimistic user bubble, updates the provisional title from the first 70 message characters/attachment name, shows working state, streams response/events, and catches up from saved history. Composer send is briefly disabled while submitting. Reasoning effort changes persist as the default preference when a nonempty option is picked.
- Typing `/` at start of text or after whitespace opens a filtered command list. Filter matches names or descriptions. Up/Down selects, Enter or Tab activates, Escape dismisses. Mouse down on a row activates without losing textarea focus. Command submission clears the composer draft. Available commands: `/new`, `/clear`, `/compact`, `/review`, `/rename`, `/fork`, `/archive`, `/copy`, `/mention`, `/permissions`, `/status`, `/usage`, `/stop`, `/clean`, plus WebUI `/files`, `/prefs`, `/export`. `/clear` starts a new thread; `/mention` opens the file gallery; `/permissions` opens preferences; `/status` displays a toast of current run/permission/usage; `/usage` refreshes provider limits then shows the same toast; `/clean` aliases Stop. `/compact` and `/review` initiate thread actions, with start toasts. `/rename` and `/fork` update/open their resulting thread.
- Shown but **unavailable / CLI only** commands: `/model`, `/fast`, `/personality`, `/plan`, `/goal`, `/diff`, `/init`, `/mcp`, `/apps`, `/plugins`, `/skills`, `/hooks`, `/memories`, `/approve`, `/agent`, `/subagents`, `/side`, `/btw`, `/resume`, `/ide`, `/ps`, `/experimental`, `/import`, `/feedback`, `/debug-config`, `/logout`, `/delete`, `/quit`, `/exit`, `/app`, `/raw`, `/vim`, `/keymap`, `/statusline`, `/title`, `/theme`, `/pets`, `/pet`, `/setup-default-sandbox`, `/sandbox-add-read-dir`. These remain visible in the menu with muted styling and a `CLI only` suffix; activating one shows an explanatory error toast. `/resume` points to the thread list. `/logout` warns that WebUI Sign out only closes its browser session. `/delete` states permanent deletion is unavailable.
- Attach via file picker (multiple), drag/drop over composer (border highlights), or pasted clipboard files. Up to 10 attachments per message, each at most 25 MB; excess and upload errors show toasts. Each uploaded item appears as a chip with filename, optional thumbnail, and remove `×` before sending. A message can consist solely of attachments; its optimistic text says `Attached …`. Gallery files are browse/open/download only; the `/mention` command does not select a gallery item into the composer.
- Microphone uses browser SpeechRecognition/webkitSpeechRecognition where supported. Its label/title/pressed state switches Start/Stop dictation; selected speech language persists locally. Starting/listening/finishing states show a status line with interim transcript, and final transcript is appended to the textarea with spacing. It handles microphone denial, no microphone/speech, network/service failures, and timeout with toasts. Unsupported browsers disable mic and language controls. It requires a secure context; iPhone home-screen mode shows an explanatory error. Sending while active waits for final transcript, and switching threads/hiding page cancels recognition.
- Sending while Codex is working stages text and attachments and shows a choice row: **Queue**, **Interrupt & send**, **Cancel**. Queue stores the message for the current thread; interrupt variant queues and clicks Stop; cancel restores staged text. Horizontal queue chips above composer show text/filenames, remove `×`, and **Retry** after a failed queued send. Messages flush automatically after the turn stops/completes. The queue is browser-local and filtered by current thread.
- The text `YOLO permissions · attachments & /commands · private network only` exists in markup as a composer note but CSS sets `.composer-note { display: none; }` at all sizes. It is not visible in the current interface.

## Activity rail and approval drawer

- Activity rail opens from **Activity** and closes with `×`; state persists locally. It has `LIVE SESSION`, `Codex activity`, pulse, `Working now`/`Waiting for work`, session token count, an optional **Execution plan**, and a **Timeline**. Empty timeline explains that reasoning, tools, edits, and checks will appear.
- Plan shows explanation or computed completion count and step number; each step has pending `○/Next`, active `→/Now`, or complete `✓/Done`. The plan is display-only. Timeline cards are timestamped and change state from running to done/error. Item kinds include reasoning summary, planning, command execution and output, file changes and patch updates, MCP server/tool name plus formatted arguments, web search query, workspace diff, turn start/completion, and generic other item types. Output detail is capped to recent 12,000 characters and scrollable. The latest turn's activity is reconstructed when opening a thread.
- Pending approval appears in a raised drawer over the main pane, with warning icon, a title and summary based on request kind (command, file change, or generic), expandable JSON **View full request**, and **Deny**, **Allow once**, **Allow for session**. Choosing sends decision, dismisses drawer, updates input-needed count, and adds a conversation event. Errors toast. A granted browser notification may alert `Codex needs input`.
- Connection/event states include live SSE updates, reconnect label, server offline toast, background-thread working indicators, periodic active-turn resync, resume after tab focus/visibility/network restore, and optional browser notification when a turn completes. Error toasts last about five seconds in the upper-right.

## Preferences modal

Opens from sidebar or `/prefs`/`/permissions`; closes with `×`, backdrop click, Escape, or **Save preferences**. It is a vertically scrollable dialog. Controls and behavior:

| Section | Controls / states |
| --- | --- |
| Chat | **Agent permissions** select: Restrictive (read-only, ask before changes), Moderate (workspace changes, ask to escape; source default), YOLO (full machine, auto-approve). **Default reasoning effort** same five choices as composer. **System prompt** multiline up to 8,000 characters, per workspace and applied on new turns. **Auto-scroll to latest**, **Auto-open activity rail on desktop**, **Notify when a turn finishes** (may ask browser notification permission), **Density** Comfortable/Compact. |
| Appearance | **Theme** Dark/Light and **Accent** Green/Blue/Purple/Gold. Theme/accent preview immediately upon selection; saved via footer. Compact density tightens message spacing/type size. |
| Archived sessions | Refresh, Select/Done, Select all/Deselect all, selected count, Restore, conditional Load more. Rows show title/date/folder and use 500 ms hold for selection and left swipe to reveal green Restore (longer swipe restores immediately). In normal mode clicking an archived row does not open it. Empty/loading states and archive/restore failure toasts. |
| Agent Media Tools (optional) | Password-style Bearer agent key input, **Save & refresh**, **Disconnect**, **Refresh status**, connection/plan/today's usage/credits status box, **Show AMT tools / allow tool hints in system context** checkbox. Connected state shows up to 40 tools with name, description, tier badge, and a scrollable list; disconnected/error state hides list. AMT usage chip appears in top bar only when connected. |

Preferences say they are stored on this machine; most chat/appearance settings actually use browser `localStorage`, while the optional AMT key is sent to local server storage. The source default is dark/green/comfortable, auto-scroll and auto-activity enabled, notifications disabled, permission mode moderate. In markup before JS runs, the permission pill says `YOLO`; JS applies the stored/default preference after initialization.

## Files & images modal and tip modal

- **Files & images** modal opens from sidebar `/files` or `/mention`; closes with `×`, backdrop, or Escape. Explains it lists recent safe file types from uploads/current workspace. Toolbar has **All files / Images / Other files** filter and **Refresh**. Grid cards show image thumbnail where appropriate (SVG and other files use glyph), filename, `source · size`, preview/open link (new tab), and download link. Empty filter result says `No matching files yet.` Loading placeholder exists in markup. Gallery is a browse view, with no inline attachment action.
- **Tip** modal opens from sidebar; closes with `×`, backdrop, Escape, or after starting checkout. It explains the product remains free; offers $3 Coffee, $7 Pizza, $15 Made my week, and custom amount. Amount/custom controls open Agent Media Tools in a new tab with a source query and optional amount. The small print mentions Stripe and no feature gate. Decorative heart icon is display-only.

## Responsive and visual behavior

- Default desktop: dark near-black palette, green accent, fixed 288 px sidebar, header, central scrollable pane, fixed bottom composer. Activity rail slides from right at up to 340 px and reduces conversation width when open. Message content is centered with generous horizontal gutters, increasing maximum width from 1280 to 1480 px at viewport width 1600 px.
- At `max-width: 760px`, sidebar is off-canvas (up to 340 px or 92 vw) with top-bar hamburger and sidebar `×`; there is no separate backdrop. Permission and run-status pills disappear. Activity button changes to an icon-like `☷`, activity rail becomes full-width, and conversation remains full width beneath it. Empty suggestions stack, folder picker stacks, avatars and spacing shrink, composer controls become larger touch targets, workspace path in composer hides, and textarea/select font is 16 px. Approval drawer expands to nearly full width with larger actions. Safe-area padding is applied around sidebar, header, composer, conversation, approval, and activity rail.
- At `max-width: 560px`, preference paired rows and AMT action row become one column; usage chips get tighter. At `max-width: 390px`, title/path ellipsis constraints tighten and tip amounts stack vertically. On mobile with height at most 620 px, empty-state logo, eyebrow, intro, badges, and suggestion buttons hide to leave folder picker accessible.
- `viewport.js` and `app.js` size and position the shell from `visualViewport` and react to resize, orientation, visual viewport resize/scroll to handle mobile browser chrome and keyboard. Login page can scroll independently. Focus outlines are present for native controls; contrast/color varies with theme and accent.

## Persistence and notable boundaries

- Browser local storage holds preferences, per-workspace system prompts, chosen dictation language, active-thread ID, individual thread/new-thread text drafts, pinned thread IDs, activity rail open state, message queue, auto-resume entries, and last chosen effort. Uploads and threads themselves are server-side. No URL deep link identifies a thread.
- The UI exposes *reasoning effort* but no active model picker; `/model` is a visible, unavailable command. It shows an execution plan and activity if the agent emits them, but `/plan` is unavailable. AMT tools are listed and context hints can be enabled, but the tools list is display-only.
- The authenticated workspace was not visually exercised because the local service requires an access password. This source inventory should be checked against a signed-in browser before treating exact real-data counts, modal rendering, and device-specific speech/keyboard behavior as runtime validated.
